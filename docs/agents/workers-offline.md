# Workers and offline behavior

Image preparation uses a dedicated module worker (`workers/photos.worker.js`) per photo and OffscreenCanvas. The upload editor aborts in-flight work when disconnected. All request promises settle on errors, cancellation or timeout; workers terminate after each photo. Browsers without Worker/OffscreenCanvas use the same processing pipeline on the page. Native WebP is preferred; `@jsquash/webp` plus its SIMD/scalar WASM encoder loads only when native encoding does not return WebP. JPEG remains the final recovery format. AVIF is not enabled: native/worker/WebP should be measured on real uploads before adding a second codec.

Selfie detection uses `workers/selfie.worker.js`, MediaPipe's ES module WASM loader and SIMD binary. Unsupported SIMD reports a recoverable browser message. Camera/video, permission, guidance and server verification remain on the page; no verification result is produced by the worker. One ImageBitmap transfers per awaited inference. Frames cannot queue; the existing 120ms interval follows completion. Dialog close, route change, page hide and startup cancellation terminate the worker and reject pending tasks. Worker code contains no React/runtime additions.

MapLibre keeps its existing worker. Filtering stays on the page while the dataset is small.

`server/offline-build.js` emits a content-versioned `sw.js` only for production builds. Dev/HMR never registers it. The precache includes app HTML, its static JS/CSS dependency graph, offline-status module, primary fonts and fixture photos; excludes editor, map/ML binaries and arbitrary APIs. Hash routes use the cached application shell from the same build. Previously requested same-origin `/assets/` and `/models/` files may be runtime-cached: max 48 entries, each <=6MiB with a known Content-Length. Other origins, query URLs, non-GET, APIs and verification traffic bypass the worker. Offline maps are not guaranteed: external map tiles are not cached. Browser-local listings and photo Blobs remain in localStorage/IndexedDB.

New builds wait for an explicit Mongolian update button. It reminds users to save unfinished work. Only the tab requesting the update reloads automatically. An offline status appears when connectivity is unavailable. Installation/cache failure leaves the online app usable. Closing the tab terminates page workers; no perpetual background compute or camera service worker exists.

Verification: Node tests cover request correlation, timeout/termination, pending cancellation, precache dependency selection, API/third-party bypass and WebP metadata restoration. Browser checks cover actual native/WASM PNG conversion, dimensions/no upscaling, blank-frame MediaPipe worker inference, offline reload and update acceptance. Real-camera/server liveness acceptance remains a separate check.
